# AI 搜答案策略共建台 · 概念 Demo

纯前端、本地 mock 的概念演示项目：商业化、行业运营、社区治理三个角色（首期）在同一个平台上共同搭建和维护 AI 搜答案卡的呈现模板与帖子筛选机制，并在固定样例上检查每次改动的影响。所有结果由本地规则引擎计算，不连接线上策略、真实模型或后端。

产品定位、范围与演示口径以 [`docs/demo-plan.md`](./docs/demo-plan.md) 为准；当前工作台结构见 [`docs/superpowers/specs/2026-11-13-workspace-restructure-design.md`](./docs/superpowers/specs/2026-11-13-workspace-restructure-design.md)；交付进度与待办见 [`TODO.md`](./TODO.md)。

## 本地运行

首次安装锁文件中的依赖后运行：

```bash
npm ci
npm run dev
```

默认本地地址为 `http://127.0.0.1:5173/`。单元测试使用 `npm test`；严格 TypeScript 检查与生产构建使用 `npm run build`；预览构建使用 `npm run preview`。运行应用和规则模拟不需要真实模型、后端或在线业务服务；首次安装依赖需从 npm registry 获取开发包。

## 页面结构

```
首页（产品介绍）
工作台
  顶栏：策略共建台 · 产品介绍 · 策略配置 · 反馈治理(开发中) │ 账号身份 ▾ · ＋新建场景 · 重置演示
  流程条：01 搭建卡片模板 ── 02 配置筛选策略 ── 03 运行回归检查
```

- 顶栏的“产品介绍 / 策略配置 / 反馈治理”是三个同级入口；当前所在的入口加粗显示（01–03 与复用向导都属于“策略配置”）。顶栏不再显示具体场景。
- 流程条吸顶，是策略配置内的步骤导航；每一步的状态由真实演示状态推导（如“草稿 v1.2 · 改动 2 项”“发现 1 条回归”）。
- **账号身份**用于权限隔离：任何账号都能查看其他角色的配置，只能修改自己负责的部分。
- **＋新建场景**：“新建空白场景”进入 01（演示中以“护肤 · 选购怎么选”为例）；“复用已有场景”进入复用向导。复用和反馈治理不在主流程内，进入时流程条隐藏。

## 从头演示主线

1. **01 搭建卡片模板**：以“行业运营 · 护肤”身份开启“按肤质分组”和“踩坑提醒”，保留默认的宽适用范围；右侧答案卡预览即时出现油皮/干皮分组和踩坑提醒（3 条引用），点开可看原文。
2. **03 运行回归检查**：显式运行 8 条独立标注样例。宽范围配置计算出 `6 提升 / 1 持平 / 1 回归`；选中“防晒和粉底的先后顺序”，查看缺失的“等待成膜”及触发规则。
3. 按回归详情建议把分组范围收窄为“选购类”，再显式重跑；固定样例结果为 `6 提升 / 2 持平 / 0 回归`。
4. **复用已有场景**：顶栏“＋新建场景 → 复用已有场景”，从“护肤 · 选购怎么选”复用到同垂类的“护肤 · 怎么使用”，生成复用报告并预览“防晒和粉底的先后顺序”。点击答案要点可检查其 mock 来源和规则 trace。

追问备用（P1）：把账号身份切换为“商业化”，在 01 的商业化页签提议把品牌说放在结论之前，查看与社区治理规则的冲突、负责人和待讨论选项，再“通知规则负责人并发起讨论”；模板草稿不会被改动。反馈治理在首页讲解完整链路，工作台内为“开发中”说明页。

策略草稿、样例运行快照和复用向导状态跨页面保存在本地演示 store 中。修改策略后不会静默覆盖上次结果：回归检查页会比较配置指纹并提示重跑。顶部“重置演示”回到策略基线、清空运行和向导状态，并回到介绍页。

## 产品介绍首页

根路径默认进入面向面试官的产品介绍页，依次说明用户痛点与项目依据、平台侧待验证假设、产品方案与价值、策略验证闭环，并把跨场景复用、反馈治理作为独立能力呈现。首页顶部导航与工作台顶栏一致，为“产品介绍（当前，加粗）/ 策略配置 / 反馈治理（开发中）”三个同级入口；“策略配置”和首屏、结尾 CTA 进入工作台的 01，首屏“先看产品方案”可定位到方案章节。工作台顶栏的“产品介绍”或品牌名可返回首页。

## 01 搭建卡片模板

定义答案卡的呈现结构。顶部显示模板名、场景锁定版本（v1.1）与草稿版本（v1.2），以及按角色记录的版本历史。左侧按角色页签查看各自负责的模块，每个页签顶部有一句职责说明；只有页签角色与账号身份一致时可编辑，否则只读并说明负责人：

- **行业运营**：一句话结论、按肤质分组及其适用范围、踩坑提醒、组件顺序。
- **商业化**：品牌说（合作内容）的呈现位置——只能提议调整，与底线规则冲突时转为待讨论，不自动采纳；“品牌说挂载商品卡”标为待研发。
- **社区治理**：锁定模块——来源底栏与溯源、合作内容标识（广告须可识别，始终开启），以及“合作内容不早于结论”底线规则。

依赖关系会置灰：“按肤质分组”关闭时，“分组适用范围”置灰并标“未生效”；组件顺序里已关闭的组件置灰、不编号、不可移动，来源底栏固定在末尾并标“社区治理锁定”。标题栏“编辑模版”弹窗可二选一：用自然语言描述想新增的卡片模块，或上传现成模版（JSON / Figma / Sketch / PDF / 图片，仅本地演示、不会上传）；提交后生成模拟工单。

右侧答案卡预览可切换改动前/改动后、突出新增/移除要点；点击要点打开溯源抽屉，查看虚构原文、笔记/评论类型、作者类型、日期、立场、引用计数和命中的规则 trace。页面底部列出“需研发 / 算法（不在此配置）”的平台边界。

## 02 配置筛选策略

决定哪些帖子进入答案卡，角色页签形式与 01 相同，生效顺序为“社区治理底线 → 商业化 → 行业运营”。规则归属原则是**谁承担规则的后果，谁负责这条规则**，每条规则的说明里写明为什么归这个角色：

| 角色 | 规则 |
|---|---|
| 行业运营（懂垂类，判断什么帖子有用） | 内容来源类型、时效窗口、笔记互动门槛（只限笔记，不限评论）、优先展示亲身经验、同肤质经验优先（只排序） |
| 商业化（管理合作内容的商业供给） | 允许合作内容进入候选、合作内容须匹配提问人群、合作品牌须有品类资质（标“对接资质库”，展示用） |
| 社区治理（守底线，其他角色不能越过） | 保留正反面经验、合作内容入卡上限（默认每卡 1 条）、处罚期账号内容不入卡（标“对接处罚记录”，展示用）、接入反馈评测结果（开发中） |

标题栏“编辑策略”弹窗只列出当前账号角色负责的策略，可逐条删除或恢复；删除后该字段取中性值（不再过滤或排序），预览和入卡帖子立即更新，“恢复本页默认”可找回。弹窗下方可用自然语言描述新增策略，提交后生成模拟工单（演示中不会真正发送）。右侧除答案卡外显示“入卡帖子变化”：相对基线新入卡和被筛掉的帖子，被筛掉的附引擎给出的原因。

## 03 运行回归检查（概念原型）

首次进入不会伪造结果，用户显式运行 8 条护肤样例；草稿与基线一致时可“载入演示改动并运行”。页面展示配置版本、独立要点覆盖、引用可追溯率、陈旧引用（对照固定的场景时效标准 180 天）、商业内容标注与逐样例差异。运行结果与本次配置快照绑定；草稿变更后保留旧结果并提示重跑。回归详情提供范围修复动作，修复后必须再次运行才能确认结果；“返回卡片模板 / 返回筛选策略”可回到对应步骤。

## 复用已有场景

复用向导按“选择来源模板 / 确认目标场景 / 查看复用报告”展开，限定在同一垂类内：从“护肤 · 选购怎么选”复用到“护肤 · 怎么使用”，共用护肤帖子池和已有组件。报告按“直接复用 / 改配置 / 待研发”分栏，所有条目沿用 01 卡片模板、02 筛选策略中的原有名称：直接复用再按“卡片模板 / 筛选策略 / 回归检查”分组（同垂类共用帖子池，02 的筛选策略全部沿用）；改配置为按肤质分组、组件顺序、固定样例集；待研发为用量与等待时长参数条。复用占比由引擎计算，planned 项不计入分子或分母。答案预览主体只使用 existing 组件，点击要点可继续查来源。生成清单后，右下角“一键生成新场景”目前弹出“开发中”说明，演示中不会真正创建场景。

## mock 数据与规则引擎

`src/data/` 包含场景与角色元数据、existing/planned 组件目录、要点目录、护肤与家常菜 mock 来源、8 条独立标注的护肤样例、卡片模板与版本、策略项，以及按角色归属的筛选规则定义（`filter-rules.ts`，含删除后的中性值和各角色职责说明）。作者、组织、发布日期和互动数均为虚构演示数据。家常菜数据目前只用于引擎单测，不再出现在复用演示中。

`src/engine/` 提供五个纯函数：`resolveConfig` 合并配置并记录字段来源，`detectConflicts` 生成待讨论护栏事项但不自动采纳，`renderAnswer` 依次应用来源类型、合作内容准入与人群匹配、笔记互动门槛、时效、正反面经验等筛选，再按同肤质、亲身经验和日期排序、按社区上限截断合作内容，最后用现有组件生成带 trace 的答案及被筛掉帖子的原因，`runCoverageCheck` 对照独立期望要点计算覆盖与引用指标，`reuseReport` 生成复用/改配置/planned 扩展清单并排除 planned 项的收益计数。

固定回归只说明本地固定 mock 上的规则模拟，不是线上实验或真实语义评测；样例期望与规则输出分开维护。
