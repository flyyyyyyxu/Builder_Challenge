# AI 搜答案策略共建平台：Manus 分阶段提示词与 UI 规范

> 用途：在 Manus 中逐段完成 `docs/demo-plan.md` 中的概念 Demo。建议先粘贴「全局前置提示词」，再按阶段逐条执行；每阶段完成并检查后再进入下一阶段。若已有项目代码或页面，要求 Manus 先读取并沿用现状，不要重建或覆盖已有工作。
>
> 原型参考：[rpt-demo.vercel.app](https://rpt-demo.vercel.app)。该页面当前讲的是商家种草笔记生成，与本项目的 AI 搜答案策略平台不是同一产品。本任务只借鉴其视觉完成度、信息分层、流程表达和可视化反馈，不沿用其产品功能、文案、指标或信息架构。

## 使用顺序

1. 在 Manus 中先发送「全局前置提示词」。
2. 按阶段 0 → 1 → 2 → 3 → 4 → 5 的顺序逐条发送。每次都让 Manus 先总结将要改什么，再实际完成本阶段，并报告完成项、未完成项和可点击的演示路径。
3. 时间充足时，再做阶段 6 的追问备用内容和阶段 7 的演示稿。
4. 每阶段验收后再继续。不要一次把所有阶段合并执行，以免核心链路尚未稳定就堆叠可选功能。

## 全局前置提示词

```text
你正在为产培 Demo Day 构建一个可交互的纯前端概念 Demo：AI 搜答案策略共建平台。请先检查当前项目文件、现有实现和 docs/demo-plan.md、docs/context-for-review.md（如果这些文件存在），在它们的基础上迭代，不要无故重建项目或覆盖已有工作。

产品定位：平台服务内部场景 PM 和行业运营。业务团队可以在不改召回、排序和模型的前提下，配置答案内容依据、答案呈现方式和适用范围；查看每条答案结论的内容来源；在固定样例上检查策略改动造成的覆盖变化和回归；把已有能力复用到新场景。

面试官必须能看懂这条主线：
1. 我在什么场景、以什么身份工作？
2. 我改了哪个策略？为什么可以改？
3. 改动具体如何影响 AI 搜答案和引用来源？
4. 固定样例发现了什么回归？如何定位原因并修复？
5. 哪些能力可直接复用到另一个场景，哪些仍需研发？

所有核心页面都要把“操作 → 直接变化 → 业务意义”讲清楚。按钮不能只有点击态；每个关键动作都要有明确结果，例如答案预览变化、溯源面板打开、样例结果更新、复用清单生成。重要状态通过可见的标签、差异高亮、前后对比和解释文字呈现，而不是要求面试官猜测。

产品边界必须诚实并在界面中可见：这是规则模拟原型，不是真实 LLM 评测；样例期望要点是独立标注；溯源表示可追踪、有依据，不代表平台为原帖真实性背书；业务可配置的是策略位，不开放召回、排序、模型调优、新数据源和新答案组件；线上收益数据不得编造。组织规则、护栏负责人和用户名称均标注为示例或虚构。

视觉参考 rpt-demo.vercel.app 的精致程度、清楚的步骤表达和结果反馈，但本项目不是营销落地页，不要复制它的 hero 大标题、商业转化 CTA、商家笔记生成功能、营销指标或移动端营销卡片结构。目标是高质量、可信、清晰的内部产品控制台，并带一个手机端答案预览。

本产品的演示场景固定为：主场景“护肤 → 选购怎么选”，问题“油皮夏天防晒怎么选”；复用场景“家常菜 → 做法步骤”，问题“海参蒸蛋怎么做”。主线顺序固定为：策略配置与溯源 → 策略覆盖与回归检查 → 修复回归 → 跨场景复用。默认身份“行业运营 · 护肤”。

实现原则：纯前端、可离线演示、mock 数据、本地状态，不接真实模型和后端。优先复用项目现有技术栈与结构；若是新项目，再采用 demo plan 中的 Vite + React + TypeScript + Tailwind CSS + Zustand + lucide-react，规则引擎用纯函数。关键流程提供合理的默认状态和可复现的演示数据。避免无功能的占位按钮、空白页和只展示静态截图的界面。

工作方式：每阶段开始先确认本阶段目标、准备修改的文件和依赖；只实现本阶段及其必要依赖，不抢跑可选模块。阶段结束时提供：完成内容、如何从界面走通本阶段、尚未完成但属于后续阶段的事项、发现的风险。不要把规则模拟效果描述成线上效果或真实语义质量。
```

## 统一 UI 与信息架构规范

### 1. 产品框架与全局导航

这是一个供面试官现场理解和操作的内部工作台，不是面向 C 端的内容消费页，也不是产品宣传页。桌面端优先，主画布建议以 1440 × 900 为基准，兼容 1280 px 宽度。全局采用左侧固定主导航、顶部上下文栏、右侧主工作区的结构；手机预览作为工作区中的专属预览面板出现，不把整个平台做成手机网页。

- **左侧主导航**：产品标识“策略共建台 · 概念 Demo”；导航项“策略配置”“覆盖与回归”“跨场景复用”；可选“反馈治理”仅在后续阶段实现。当前项有清晰选中状态。底部固定一条“规则模拟原型”状态标识。
- **顶部上下文栏**：场景路径（护肤 / 选购怎么选）、身份（行业运营）、演示数据版本或草稿状态。场景和身份在视觉上可辨认，但不要让全局切换抢走主任务注意力。
- **工作区标题区**：每页标题、简短目的说明、当前步骤状态。标题说明“这页要完成什么”，副说明解释“为什么要做”。主要操作按钮放在标题区或明确的局部操作区。
- **主工作区**：以清晰分栏承载控制项与结果。配置类页面默认左边为策略表单、右边为答案预览；回归页默认左边为样例列表、右边为选中样例的完整追踪；复用页以步骤导航加三栏复用清单为核心。
- **说明与边界**：使用轻量信息提示、折叠区或行内注释。不要把关键免责声明藏在脚注、Tooltip 或演示者口述里。

### 2. 页面固定的“操作—结果”表达

每个核心页面在首屏内尽量回答三个问题：

- **我现在在做什么？** 用页面标题和一句简短说明回答。
- **我可以操作什么？** 控件名称直接对应业务概念，并标注适用范围、设置者或只读原因。
- **操作之后会怎样？** 明确展示结果区域；改动项高亮，显示变化前后和影响范围。关键按钮旁避免只写“提交”“完成”这类抽象文案，优先写“应用策略并更新预览”“运行 8 条样例”“收窄到选购类并重跑”“生成复用清单”。

### 3. 字体与字号

使用系统字体栈，确保中文稳定清晰，不依赖在线字体才能正确显示：`Inter, -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。

- 页面主标题：24–28 px，字重 600；每页只出现一个主标题。
- 区块标题：18–20 px，字重 600。
- 卡片标题：15–16 px，字重 600。
- 正文与控件标签：14–15 px；关键说明文字不低于 14 px。
- 辅助信息、时间、来源元数据：12–13 px；免责声明和重要状态不低于 13 px，不能用低对比度灰字弱化。
- 数值与状态：字号 20–28 px，仅用于真正需要被扫读的计数或结果，不用大数字制造虚假增长感。
- 行高：正文约 1.5；标签、按钮约 1.3。保证中英文混排、长问题和来源片段不挤压或截断。

### 4. 布局与尺寸

- 左侧导航约 224 px，顶部栏约 60–64 px；主内容左右留白 28–36 px，区块间距 24–32 px。
- 配置页使用“策略工作区 + 手机预览”双栏布局。预览面板建议 340–400 px，保持手机框比例；策略表单区域占剩余宽度。不要把整页压成三列小卡片。
- 策略项按三个清晰页签组织：内容依据、答案呈现、护栏规则。每页签建议 5–6 个以内可见项目；用简短解释补足术语，不堆满开关。
- 手机预览展示一条完整、可读的 AI 搜答案，不要只画手机外框。结论、按肤质分组、踩坑提醒、来源底栏和可点击溯源都要能辨认。
- 1280 px 下优先压缩留白和调整预览宽度，不缩小正文到难读；更窄视口可转为上下布局。

### 5. 视觉语言

采用克制、可信、具有产品工具感的视觉语言：暖白或浅灰页面底色、白色主工作面、深灰正文、单一清晰的品牌强调色，以及少量状态色。用细边框和轻微层级区分内容，不用大面积渐变、强烈玻璃拟态、重阴影或装饰性插画。状态色需有文字标签配合，不能只靠颜色表达。

“真实来源与策略影响可解释”是产品的视觉核心：使用来源标签、规则范围标签、变化高亮、前后对比、结果解释卡等一致的模式。待研发扩展点用虚线边框和“待研发”标签；示例护栏用“示例规则”标签；未经验证的产品假设用“待验证”标签。

动效只用于帮助用户理解状态变化：预览变更短暂高亮、页签切换、面板展开、运行结果刷新。避免循环动画、浮夸入场和影响现场讲解的动效。支持减少动态效果的系统偏好。

### 6. 示例文案风格

- 主张清晰、克制，不夸大：“让策略改动看得见，让固定样例里的回归查得到。”
- 主按钮描述操作和对象：“应用策略并更新预览”“运行 8 条样例”“收窄到选购类并重跑”。
- 结果说明写出因果：“分组规则同时作用于用法类问题，导致‘等待成膜’要点被拆散。将适用范围收窄到选购类后，这条回归消失。”
- 边界说明完整：“规则模拟原型，用于检查策略改动对固定样例的影响，不代表语义判断准确率。”
- 溯源说明完整：“溯源保障可追溯、有依据，不代表平台为帖子真实性背书。”
- 不使用“智能赋能”“全链路闭环”“效果提升 80%”等空泛或无证据文案。

### 7. 无障碍与现场演示可读性

按钮、页签、表单均可用键盘操作并有清晰焦点状态；点击区域足够大；正文和状态文字保持足够对比度；输入控件有可见标签。关键状态不能只用颜色区分。首次打开时确保样例、默认策略、回归路径已有演示数据，避免面试官遇到空页面。提供“重置演示状态”或等价能力，避免上一次操作污染下一次演示。

# 分阶段提示词

## 阶段 0：检查现状并搭建产品骨架

**目标**：先让面试官知道平台是什么、谁在用、从哪里开始、整段演示怎么走。暂不实现完整业务逻辑。

```text
执行阶段 0：检查当前项目并建立 AI 搜答案策略共建平台的产品骨架。

先检查现有项目结构、框架、运行方式和已有页面。若项目已存在，复用当前结构；若尚未初始化，再依据全局前置提示词中的技术栈建立最小可运行应用。不要在本阶段实现完整规则引擎、样例结果或复用业务逻辑。

本阶段必须交付：
1. 全局工作台框架：左侧导航、顶部场景/身份上下文、主内容区、产品名称和“概念 Demo / 规则模拟原型”状态。
2. 三个核心导航入口：策略配置、覆盖与回归、跨场景复用。未完成的页面可以有明确说明的轻量骨架，但导航点击必须有结果，不可是死链接。
3. 一个策略配置首页的首屏结构：场景“护肤 → 选购怎么选”、问题“油皮夏天防晒怎么选”、身份“行业运营”；明确展示“配置策略 → 查看答案和来源 → 检查回归 → 复用到新场景”的演示步骤。
4. 设计 token 或等效统一样式：颜色、字号、间距、圆角、边框、阴影、按钮和状态标签。按统一 UI 规范执行，保证 1440 px 和 1280 px 宽度清楚可读。
5. 使用具体、克制的中文内容；不要使用“欢迎来到平台”之类空文案。

请在首页或主工作区显性说明平台边界：业务可配置内容依据、已有答案组件开关/顺序、生效范围和样例集；不配置召回、排序、模型、新数据源和新组件。

完成后启动应用并确认可打开。回复我：已有项目结构如何复用、创建/修改了哪些文件、如何进入四步演示主线、哪些页面目前只是骨架。不要提前做 P1 反馈治理、商业冲突或叙事页。
```

**阶段验收**：打开后 10 秒内能看懂产品定位、用户是谁、首个操作入口和演示主线；所有导航入口有明确反馈；画面不是营销 Landing Page。

## 阶段 1：建立可信的演示数据与规则模拟引擎

**目标**：先确保业务逻辑和因果链成立，再接页面，避免页面视觉完整但数据互相矛盾。

```text
执行阶段 1：实现 demo-plan.md 中的数据模型、mock 数据和纯函数规则模拟引擎。本阶段优先正确性，不做页面视觉重构，也不新增后端或真实 LLM。

先复用当前项目中的类型和数据结构；缺少时再补足。至少覆盖：场景与身份、策略项与设置者、帖子/评论及来源元数据、答案模型、固定样例及独立标注期望要点、组件库（existing / planned）、冲突类型。按 demo-plan 中的字段语义实现，不要删掉“规则模拟”“来源可追溯但不背书”“独立标注”等产品边界。

实现并验证这些纯函数：
- resolveConfig：得到生效配置、设置者、来源和适用范围。
- detectConflicts：发现示例护栏冲突，只给出待讨论选项和负责人，不自动采纳。
- renderAnswer：根据配置、问题类别和 mock 帖子生成答案，答案要点来自引用内容与可承载组件的交集，并按适用范围过滤。
- runCoverageCheck：逐条对比改动前后输出、独立期望要点覆盖、引用可追溯、陈旧引用、未标注商业内容，并说明变化。
- reuseReport：生成直接复用、需改配置、待研发扩展三栏清单；planned 组件不得计入复用收益。

固定演示因果：开启“按肤质分组”后，8 个护肤样例显示 6 条提升、1 条持平、1 条回归。回归样例是“防晒和粉底的先后顺序”，期望要点包括“等待成膜”；分组规则意外作用到“用法类”问题，导致要点拆散/遗漏。将规则适用范围收窄为“选购类”后重跑，回归消失。家常菜答案主体只用 existing 组件；“参数分布条”必须标为 planned，不能算入复用。

为引擎写必要的单元测试，覆盖规则范围、来源追踪、回归复现与修复、planned 组件不计入复用等关键行为。不要为了凑通过率而直接硬编码结论数字；结果应由配置和样例数据计算得出。若原 demo plan 的数据条数与阶段时间不完全匹配，优先保留演示链路所需的可信数据与字段，不要编造线上指标。

完成后报告：核心数据文件、引擎函数、测试结果；说明回归如何被触发以及如何消失；标出所有示例/虚构信息。此阶段不要实现新的 UI 页面功能。
```

**阶段验收**：规则引擎可复算；回归在错误适用范围下稳定出现，收窄范围后消失；测试覆盖上述关键因果；数字不是静态写死的装饰。

## 阶段 2：策略配置页、手机预览与溯源

**目标**：走通主线第一段，让面试官看到“改了什么、答案怎么变、结论从哪里来”。

```text
执行阶段 2：基于已完成的数据和规则引擎，完成策略配置页、手机端 AI 搜答案预览、前后对比和溯源面板。严格复用现有全局 UI 框架和统一规范，不要改成宣传页。

默认场景为“护肤 → 选购怎么选”，问题“油皮夏天防晒怎么选”，身份“行业运营”。策略页包含三个页签：内容依据、答案呈现、护栏规则。每个策略项需要展示名称、当前设置、适用范围、设置者/负责人和简短解释。示例护栏只读，明确标注“示例规则”和负责团队。页签中的可见策略项控制在 5–6 个以内。

实现以下交互：
1. 开启“按肤质分组”和“踩坑提醒”后，实时调用答案引擎更新右侧手机预览。
2. 预览可切换“改动前 / 改动后”或等价并排对比。被改变的结论、分组、提醒区域短暂高亮；提供一句话说明发生了什么变化。
3. 手机答案至少包含一句话结论、油皮/干皮分组、踩坑条（示例：“3 人反馈和粉底一起用会搓泥”）、来源底栏。
4. 点击一条结论或踩坑提醒，可打开溯源面板，展示原文片段、发布时间、内容类型、正反面计数、作者类型。明确说明“溯源保障可追溯、有依据，不代表平台为帖子的真实性背书”。
5. 页面底部提供可折叠区“需研发/算法（不在此配置）”，列出召回、排序、模型选择与调优、新组件和新数据源。

主按钮和交互文案使用明确结果，例如“应用策略并更新预览”“查看引用来源”。确保控制项与手机预览在 1440 和 1280 px 下同时可读；更窄宽度时可以上下堆叠。提供一键恢复默认配置，保证演示可重置。

完成后按照面试官视角报告一条完整操作路径：初始答案是什么、开启了什么、预览改变了什么、点击结论能看到什么、哪些能力明确不在业务配置范围内。不要加入虚构收益数字。
```

**阶段验收**：面试官无需口头补充即可看懂策略操作如何改变答案；点击结论必有来源证据；免责声明和平台边界在首屏流程中可见。

## 阶段 3：策略覆盖与回归检查

**目标**：完整演示固定样例如何发现、解释并修复一条回归，且不把概念原型包装成质量评测。

```text
执行阶段 3：完成“策略覆盖与回归检查”页面，接入阶段 1 的规则引擎，并与策略配置使用同一份全局状态。页面名称和所有说明都使用“策略覆盖与回归检查（概念原型）”或“规则模拟”，禁止写成“答案质量评测”或语义准确率。

页面首屏展示：固定护肤样例集、8 条样例的总体变化、独立标注说明，以及一条明显可进入的回归样例。统计结果必须实时由引擎计算。展示要点覆盖、引用可追溯、陈旧引用、商业内容未标注等检查项；同时明确标注“用于检查策略改动对固定样例的影响，不代表语义判断准确率”。

回归样例详情必须按以下顺序完整呈现：
1. 用户问题：“防晒和粉底的先后顺序”。
2. 期望要点（由场景负责人独立标注/复核），其中包含“等待成膜”。
3. 改动前输出与改动后输出，明确高亮遗漏的要点。
4. 原因解释：按肤质分组规则误作用于“用法类”问题，导致步骤要点被拆散或截断。
5. 可执行修复：“将按肤质分组的适用范围收窄到选购类”，要求显示修改前后的范围。
6. “收窄到选购类并重跑”操作。执行后重新计算结果，并明确显示这条回归消失、遗漏要点恢复。

样例列表可选中不同样例；总体数值、详情和重新运行结果必须来自同一状态。加入“重置演示状态”。不得只改变一枚绿色标签而不重跑引擎。页面说明样例维护机制：由场景负责人维护，改动人不能单独判定通过；线上问题可补入样例集，具体责任人待业务确认。

完成后用最短点击路径实际走通一次“看到回归 → 查看原因 → 收窄范围 → 重跑 → 回归消失”，并报告每一步页面向面试官传达的信息。
```

**阶段验收**：主线第二段可在 90 秒左右演示；错因、操作和修复结果一一对应；所有检查口径均明确限定为规则模拟和固定样例。

**目标**：展示平台能复用已有策略与组件，同时诚实标出不适配和待研发能力。

```text

向导可以分为三步：选择来源模板、确认目标场景和问题、检查并生成复用清单。步骤标题要让面试官看懂当前进度；如果三步动画会影响演示效率，可直接逐步呈现，不必做复杂动画。

生成三栏清单：
- 直接复用：已有组件和策略能力；每项说明为何可复用。
- 需要改配置：说明从护肤场景的参数/分组/内容依据如何调整为做法步骤。
- 待研发扩展点：参数分布条，使用虚线边框并标注“概念预览，非平台已有能力”。此项不得计入复用收益。

主要操作按钮使用“生成复用清单”或“查看目标场景预览”。页面结束处用一句话总结“哪些能力带得走、哪些需要重新配置、哪些要研发”，并提供回到护肤配置的入口。

完成后按主线第三段走一遍，确认“家常菜预览”与“复用清单”状态一致，planned 能力没有被计入复用。
```

**阶段验收**：面试官能区分复用、重配置和待研发；复用价值不是由新增组件撑起来；家常菜主体可读、来源可追溯。

## 最终演示路径（给面试官的可见流程）

1. **策略配置**：面试官看到当前身份和“护肤 → 选购怎么选”，开启按肤质分组与踩坑提醒。右侧答案即时变化，点击结论可查来源。此步证明业务经验如何作用于答案，同时说明来源可追溯不等于真实性背书。
2. **覆盖与回归**：面试官运行 8 个固定样例，看到总体覆盖变化，再进入“防晒和粉底的先后顺序”。页面用期望要点、改前/改后输出和规则适用范围，解释“等待成膜”为何遗漏。
3. **修复并重跑**：面试官将分组范围收窄到选购类，再次运行。回归消失且要点恢复。页面说明这是规则模拟和独立标注样例，不是语义质量或线上效果评测。
4. **跨场景复用**：面试官创建家常菜做法场景，看到直接复用、改配置和待研发扩展点三类清单，再查看“海参蒸蛋怎么做”的答案预览。主体仅使用已有组件，参数分布条明确排除在复用收益之外。

整个过程始终围绕一个可复述的问题：**业务策略的改变如何影响 AI 搜答案，影响是否可追踪、可检查，以及哪些能力可以跨场景复用？**
