# 规则引擎与策略配置页：详细交互设计

> 本文是 `docs/manus-prompts-and-ui-spec.md` 的细化补充，聚焦两件事：策略配置页上每个操作如何工作，以及规则引擎如何把一次配置改动转换为可解释的答案变化和样例检查结果。面向产培 Demo Day 的纯前端概念原型，不代表真实线上架构或语义评测能力。

## 1. 交互目标与原则

面试官在策略配置页停留约 90 秒后，应能复述：

1. 当前由谁、针对哪个问题场景配置答案策略。
2. 业务改动的是内容依据和答案呈现策略，而不是召回、排序或模型。
3. 改动如何改变答案结构，以及每条结论如何回到原始内容。
4. 改动如何进入固定样例回归检查，并如何定位策略适用范围过宽造成的遗漏。

页面的反馈链路统一为：

> **策略项改变 → 答案预览重新计算 → 差异被标出 → 可查看来源与规则解释 → 可前往固定样例检查影响**

所有交互遵守以下原则：

- 不让面试官猜测按钮效果。主操作名称包含动作和对象，如“运行 8 条样例”。
- 修改后即时更新预览。无需点击一个含义模糊的“保存”按钮才看到变化。
- 区分“初始基线”和“当前草稿”。前后对比基线在本次演示中保持不变，避免用户改一次基线也跟着改变、导致对比失效。
- 每个结果都可以追溯到具体配置、规则、样例或来源记录。
- 只读项说明只读原因；待研发能力不伪装成可配置开关。
- 用标签和文字共同表达状态，不只使用颜色。

## 2. 页面骨架与信息区域

### 2.1 页面整体布局

桌面端采用三层结构：

1. **全局上下文栏**：产品名、场景路径、当前身份、演示状态。
2. **页面标题与步骤**：标题“策略配置”，说明“调整业务可配置策略，并即时查看答案变化”；步骤轨迹“配置策略 → 查看来源 → 检查回归 → 跨场景复用”。当前高亮第一步。
3. **主工作区双栏布局**：左侧策略控制区约占 58%–62%，右侧手机端答案预览约占 38%–42%。手机预览建议宽度 360 px 左右；小于 1280 px 时降低列间距或切换上下布局，不压缩正文。

左侧策略区由场景问题条、三页签、策略项和页脚操作组成。右侧预览顶部有“改动前 / 改动后”切换、变化摘要和手机预览。页面最底部有折叠的“需研发/算法（不在此配置）”区。

### 2.2 首屏需要出现的信息

- 场景：`护肤 / 选购怎么选`
- 当前问题：`油皮夏天防晒怎么选`
- 当前身份：`行业运营`
- 配置状态：`初始策略`或`草稿有改动`
- 一句说明：`改动会即时更新右侧答案预览；固定样例检查用于观察改动影响。`
- 显性边界：`可配置答案策略，不改召回、排序和模型。`

不要将以上信息都放进下拉菜单、tooltip 或页面底部。面试官刚进入页面就要知道自己处在什么场景和阶段。

## 3. 策略配置的状态模型

### 3.1 必须区分的状态

建议用一个全局 store 管理以下状态。具体技术实现可按项目现状调整，但语义必须保留。

```ts
type DemoState = {
  role: 'industry_ops' | 'dots_pm' | 'ads' | 'community';
  sceneId: string;
  queryId: string;
  activeTab: 'evidence' | 'presentation' | 'guardrail';

  baselineConfig: StrategyConfig; // 本次演示前的固定基线，创建后不随普通编辑变化
  draftConfig: StrategyConfig;    // 当前正在编辑的配置
  previewMode: 'before' | 'after';
  selectedEvidenceId?: string;
  openPanel?: 'evidence' | 'change-log' | 'boundary';

  lastCheckRun?: CoverageRun;     // 最近一次显式运行样例的结果
  demoVersion: number;            // 每次重置或新演示版本递增
};
```

`baselineConfig` 是默认配置的不可变快照。`draftConfig` 初始时深拷贝基线。每次改动 `draftConfig` 后，即时重新计算“改动后”预览。切换“改动前 / 改动后”只切换当前展示，不改变配置。

样例检查以显式运行作为一个新的结果版本。用户修改策略后，旧检查结果不得伪装成当前配置的结果。若策略与上一次检查时不同，应显示：`策略已有未检查改动 · 上次检查基于版本 N`，并提供“运行 8 条样例”。

### 3.2 状态与动作的关系

| 用户动作 | 页面状态变化 | 可见反馈 |
|---|---|---|
| 改动任一策略控件 | 更新 `draftConfig`，增加策略版本 | 状态变为“草稿有改动”；右侧改动后预览即时重算；改变区域高亮 |
| 切换“改动前” | `previewMode = before` | 显示 `baselineConfig` 生成的答案，并标注“基线” |
| 切换“改动后” | `previewMode = after` | 显示 `draftConfig` 生成的答案，并标注“当前草稿” |
| 点击答案要点 | 设置 `selectedEvidenceId` | 打开来源面板，展示原文、元数据和覆盖该结论的引用关系 |
| 撤销改动 | 将 `draftConfig` 恢复至 `baselineConfig` | 状态回到“初始策略”；预览差异消失；上次运行结果仍显示其历史版本，不冒充最新结果 |
| 前往“覆盖与回归” | 保留当前 `draftConfig` | 检查页提示将以当前草稿运行样例 |
| 重置演示 | 恢复基线、关闭抽屉、清除临时选择和旧结果 | 提示“演示状态已重置”；返回策略配置默认状态 |

### 3.3 修改保存方式

本概念 Demo 没有后端持久化，因此不使用“已发布”“线上生效”或“保存到生产”措辞。用户编辑的是本地草稿。建议在策略区底部提供：

- 状态文字：`本地演示草稿 · 修改实时预览`
- 次要操作：`恢复初始策略`
- 主要操作：`前往覆盖与回归`

如果需要本地存储，刷新后恢复的是演示草稿，也必须明确标注“本地保存”，不可显示为线上策略已发布。

## 4. 策略页签与控件的具体交互

策略页签共三项：内容依据、答案呈现、护栏规则。每项策略至少展示：名称、当前值、适用范围、设置者/负责人、简短解释。每个页签控制在 5–6 个可见项目内。

### 4.1 内容依据

| 策略项 | 控件形式 | 触发的引擎变化 | 预览中的可见反馈 |
|---|---|---|---|
| 优先展示亲身经验 | 开关 | 提高 `firstHand` 帖子在候选来源中的优先级；不把非亲身经验伪装为亲身经验 | 来源列表排序和“经验来源”标签变化；若当前选中来源被替换，显示简短解释 |
| 内容来源类型 | 多选控件：笔记 / 评论 | 过滤候选来源；若取消某一类型，答案中只能引用剩余允许类型 | 来源底栏计数更新；受影响的结论高亮；无可用来源时明确提示，不生成无依据结论 |
| 时效窗口 | 单选或下拉：如 90 天 / 180 天 / 365 天 | 按发布时间过滤陈旧候选内容 | 来源项显示发布时间；过期内容被排除时，变化摘要解释“超出当前时效窗口” |
| 商业内容标注 | 开关，只允许开启标注，不提供隐藏标注的默认操作 | 商业合作内容仍可进入候选池，但渲染时携带商业标注状态 | 来源卡或答案底栏显示商业内容已标注数量；若示例合作内容未标注，检查结果计入“未标注商业内容” |
| 正反面内容并列 | 开关或选择项 | 保留推荐、不推荐、踩坑等不同立场的来源 | 预览显示分歧提示或正反来源入口；不能把立场计数描述成真实性证明 |

细节要求：来源筛选和时效规则可能导致某条结论没有证据。此时应显示“当前策略下没有满足条件的引用”，而非静默生成结论或引用不匹配内容。

### 4.2 答案呈现

| 策略项 | 控件形式 | 触发的引擎变化 | 预览中的可见反馈 |
|---|---|---|---|
| 按肤质分组 | 开关；旁边显示适用范围选择器 | 对匹配范围内的样例按肤质分组渲染。默认范围为“选购类 + 用法类”，用于产生预设回归；后续可收窄为“仅选购类” | 预览的分组标题和答案要点顺序变化；“改动后”区域高亮；若范围包含用法类，显示“此范围也会影响用法问题”的轻提示 |
| 踩坑提醒 | 开关 | 从踩坑类/负向经验来源提取有据可查的提醒 | 显示或隐藏提醒卡；提醒句旁可点开来源；没有支持证据时显示“暂无足够来源”，不能编造人数 |
| 一句话结论 | 开关或组件顺序控制 | 根据符合条件的来源生成/展示结论条 | 预览首段结论是否显示；结论必须关联来源，不以无来源总结填空 |
| 答案组件顺序 | 有序选择或上下移动按钮 | 改变现有组件的渲染顺序 | 预览实时调整；注明仅改变呈现顺序，不改变召回和模型 |
| 显示来源底栏 | 开关，默认开启且可说明平台默认要求 | 控制来源数量、内容类型和最新时间摘要的展示 | 预览底栏同步变化。若关闭导致无法理解引用，建议用只读信息解释或禁用该操作，避免掩盖关键溯源信息 |

**按肤质分组的范围选择器**是演示回归的核心。使用清晰的多选标签或选项：`选购类`、`用法类`、`做法类`、`踩坑类`。默认选中“选购类”和“用法类”，旁边说明“当前策略影响 2 类问题”。用户收窄为“选购类”后，状态摘要应显示“当前策略影响 1 类问题”。不要只把范围藏在齿轮或高级设置中。

### 4.3 护栏规则

护栏是只读示例，不能由普通身份直接开关或编辑。列表项建议显示：

- 规则名称与说明。
- 来源团队，例如“社区治理”。
- 负责人姓名（虚构）和规则版本/更新时间（示例）。
- 适用对象与规则状态。
- 锁定图标和“示例护栏 · 只读”标签。

如用户当前改动触发护栏冲突，只显示“检测到冲突”“规则来源”“负责人”和“待讨论的选项”。提供“查看冲突详情”或“通知负责人并发起讨论”的概念操作。点击之后展示“已生成待讨论事项（概念演示）”，不能自动调整业务配置、不能自动采纳选项，也不能显示真实协作请求已发送。

### 4.4 设置者与权限说明

每个策略项的设置者是记录元数据，不代表平台已经实现完整权限系统。展示样式可为：`行业运营 · 林同学 · 示例`。只读项说明“由社区治理示例规则维护，本 Demo 不开放编辑”。若身份切换为非授权角色，可把控件置灰并说明“当前身份无此策略位编辑权限（概念示例）”，但不得宣称真实权限流程已经落地。

## 5. 手机端答案预览的交互

### 5.1 预览顶部

预览卡顶部必须显示：

- 标题：`AI 搜答案预览`
- 当前模式：`改动前 · 初始基线`或`改动后 · 当前草稿`
- 前后切换控件
- 变化摘要，例如：`新增按肤质分组；新增 1 条踩坑提醒`
- 当前策略状态，如：`本地草稿，尚未运行样例检查`

### 5.2 答案结构

主场景预览至少由下列结构构成，内容避免过小：

1. 用户问题：`油皮夏天防晒怎么选`。
2. 一句话结论（如当前策略启用）。
3. 油皮 / 干皮等分组（只有分组策略启用时出现）。
4. 踩坑提醒（仅在有匹配证据时出现）。
5. 支持结论的原文引用入口，每条引用带来源类型和时间。
6. 来源底栏：笔记、评论、商业内容等计数，以及最新内容时间。
7. 固定溯源提示：`可追溯、有依据，不代表平台为帖子的真实性背书。`

### 5.3 前后差异呈现

- `改动前`展示由 `baselineConfig` 计算的答案，不随草稿改变。
- `改动后`展示由 `draftConfig` 实时计算的答案。
- 新增内容用“新增”标签及轻量高亮；移除内容在比较视图中用删除态显示，不能在普通答案视图里长期保留误导性内容。
- 变化摘要由 diff 结果生成，至少描述结构变了什么、引用数量变化多少、哪些内容被增加或移除。
- 如果配置修改没有造成答案变化，明确显示“此改动未影响当前示例问题，可能是该规则不适用于此问题”，并可链接到策略适用范围。

### 5.4 点击结论打开溯源面板

点击结论、分组条目、踩坑提醒或引用数量，应打开右侧抽屉或预览区下方详情面板。桌面端不遮挡当前问题和答案上下文；面板至少包含：

- 当前结论/要点。
- 引用条数及其与结论的对应关系。
- 原文片段，关键支撑短句高亮；不可只展示标题。
- 内容类型：笔记 / 评论；作者类型：素人 / 博主 / 合作。
- 发布时间、亲身经验标识、立场（推荐 / 不推荐 / 踩坑 / 中立）。
- 正反面计数（若有），注明是 mock 样例计数。
- 引用来源是否符合当前时效、内容类型和亲身经验设置。
- 如被过滤，说明过滤规则，例如“超过 180 天时效窗口”。
- 免责声明：“溯源保障可追溯、有依据，不代表平台为帖子的真实性背书。”

抽屉可通过关闭按钮、Esc、点击返回关闭。打开后保留当前预览模式和选中的答案位置。

## 6. 规则引擎的输入、计算和输出

### 6.1 引擎负责什么，不负责什么

规则引擎是本地纯函数集合，依据固定 mock 数据和显式配置产生可复现结果。它用于演示策略影响路径，不判断真实语义质量，不调用真实模型，不代表线上推荐、召回或用户收益。

引擎应能回答：

- 哪些策略对当前问题生效，规则从哪里来，由谁设置？
- 哪些帖子/评论符合来源条件？哪些被过滤，原因是什么？
- 答案由哪些已有组件和内容要点构成？
- 当前问题的要点是否被固定样例的独立期望要点覆盖？
- 哪条引用不可追溯、过期或商业标注缺失？
- 策略变化是否造成回归，回归原因是什么？

引擎不回答：

- 哪篇帖子实际上为真、哪位用户可信。
- 生成答案的语义准确率或真实用户满意度。
- 策略上线后带来多少业务收益。

### 6.2 建议数据契约


### 6.3 确定性计算管线

建议将一次答案渲染拆成有序步骤。每一步返回结果和解释记录，不将所有逻辑塞进一个大型组件。

1. **解析配置来源**：合并平台/模板默认值与场景配置，记录每个字段由谁设置、是否可编辑。Demo 使用固定优先级，避免数据冲突时结果不确定。
2. **识别问题类别**：使用 mock 查询对象中显式标注的类别，不在这个 Demo 中伪称系统完成了真实意图识别。
3. **候选来源筛选**：按来源类型、时效窗口等过滤帖子/评论。每条被过滤内容记录原因。
4. **来源排序**：亲身经验优先、立场平衡等规则只改变确定性排序，不改变内容真实度判断。排序 tie-breaker 固定，例如按日期和 id 排序。
5. **要点与组件匹配**：只有来源中存在、且现有组件能够承载的要点才进入答案。planned 组件不能承载当前正式预览中的主体内容。
6. **适用范围判断**：针对每项呈现策略检查 `query.category` 是否在 `appliesTo` 中；不适用时记录“该策略未对当前问题生效”。
7. **呈现组装**：按组件顺序、分组和踩坑开关组装答案。每个答案要点保留来源 ID 和规则 trace。
8. **计算底栏和变更 diff**：统计来源与标注信息；对比基线答案和草稿答案，得到新增、移除、未变化项。

任何规则修改都必须使输出可复算。不要在 UI 中写死“改动后出现三条”“复用率 80%”等固定装饰数值；应由输入数据计算。

### 6.4 回归样例如何确定性触发

回归案例是有意设计的规则模拟，不是随机缺陷。默认 `groupByPersona = true`，且 `groupByPersonaAppliesTo` 同时包含“选购类”和“用法类”。在 `用法类` 问题上，分组呈现会把步骤要点拆到不同分组；示例规则每个分组仅呈现有限数量的步骤要点，因此“等待成膜”被截断而未进入最终答案。每一步都在 trace 中记录：

- `分组规则生效：问题类别“用法类”属于当前适用范围。`
- `步骤要点“等待成膜”符合来源条件，但在分组后的呈现限制中被截断。`

用户把适用范围改为只包含“选购类”后，该问题不再触发分组。答案使用原步骤顺序呈现，“等待成膜”恢复。trace 应记录：

- `分组规则未生效：问题类别“用法类”不在当前适用范围。`
- `要点“等待成膜”由现有步骤组件承载并保留。`

必须在界面注明：这是可解释的规则模拟示例，用于展示配置范围对固定样例的影响，并不代表真实系统的语义判断过程。

### 6.5 固定样例检查口径

每个样例包含问题、类别、独立标注的期望要点及标注人/复核状态。期望要点不从被测输出反向生成。

建议输出：

```ts
interface SampleResult {
  sampleId: string;
  before: RenderedAnswer;
  after: RenderedAnswer;
  expectedPointKeys: string[];
  coveredBefore: string[];
  coveredAfter: string[];
  missedBefore: string[];
  missedAfter: string[];
  traceableRateBefore: number;
  traceableRateAfter: number;
  staleCountBefore: number;
  staleCountAfter: number;
  sponsoredUnlabeledBefore: number;
  sponsoredUnlabeledAfter: number;
  delta: 'improved' | 'same' | 'regressed';
  reason?: string;
}
```

定义要清楚且可复算：

- **要点覆盖**：`coveredExpectedPoints / expectedPoints.length`。某个期望要点只有在答案中出现，且可关联到至少一条符合来源条件的证据时，才算覆盖。
- **引用可追溯率**：`可解析的引用数 / 答案中的引用总数`。无引用时显示“无引用”，不除以零。
- **陈旧引用数**：不符合当前时效窗口的最终引用数。被正常过滤的内容不算“最终引用”。
- **商业内容未标注数**：答案使用的商业内容中没有商业标签的条数。
- **单样例变化分类**：要点覆盖增加且无护栏指标恶化为 improved；要点覆盖和护栏指标均无变化为 same；关键期望要点遗漏增加或护栏指标恶化为 regressed。具体判断条件写进代码常量或文档，避免口径隐藏在 UI。

样例集总体结果可以展示 6 条提升、1 条持平、1 条回归，但必须来自 8 条样例逐条计算。进入回归详情时，所有卡片、比例和根因必须对应同一运行版本。

## 7. 完整主线操作脚本与逐步反馈

| 序号 | 用户操作 | 系统响应 | 面试官应看到/理解 |
|---|---|---|---|
| 1 | 打开“策略配置” | 加载护肤选购场景、行业运营身份和默认基线 | 这是业务配置台，场景和操作者明确 |
| 2 | 进入“答案呈现”页签 | 展示按肤质分组和踩坑提醒策略及适用范围 | 配置的是既有策略位，不是调模型 |
| 3 | 开启按肤质分组 | 更新草稿，实时重算“改动后”预览，展示按肤质分组 | 用户动作立即改变答案组织方式 |
| 4 | 开启踩坑提醒 | 出现带证据的提醒卡并高亮，显示有几条来源支持 | 策略不仅改变排版，也能组织负向经验 |
| 5 | 点击提醒或结论 | 打开溯源抽屉，展示原文、时间、类型、立场和对应关系 | 答案有来源链路；平台不为原帖真实性背书 |
| 6 | 点击“前往覆盖与回归” | 带着当前草稿进入检查页，并提示样例尚未按该草稿重跑 | 预览改变不是检查结论，仍要检查固定样例 |
| 7 | 运行 8 条样例 | 引擎生成带版本号的检查结果 | 结果基于当前配置和独立标注期望要点 |
| 8 | 打开“防晒和粉底的先后顺序” | 逐层显示期望要点、前后输出、缺失点和规则 trace | 回归来自策略范围过宽，根因可追踪 |
| 9 | 把分组范围改成“仅选购类”并重跑 | 更新草稿并重新计算样例，恢复“等待成膜”要点 | 修复是针对范围，而不是手工改结果 |
| 10 | 进入跨场景复用 | 使用明确版本的护肤模板创建家常菜场景 | 策略与组件复用进入下一段主线 |

### 7.1 页面与跨页状态规则

- 策略配置页和覆盖检查页共用同一个 `draftConfig`。
- 覆盖检查结果记录生成时的 `configVersion`。配置变化后显示旧结果版本，不静默替换。
- “收窄范围并重跑”可以在回归详情内提供快捷编辑控件，但必须确实更新 `draftConfig` 后调用检查引擎。
- 用户从检查页返回配置页时保留当前草稿、当前问题、页签和必要上下文。
- 复用向导读取明确选定的来源模板版本，不能将未验证草稿伪装成正式模板。
- 重置时统一恢复基线并清除依赖旧配置的检查结果或将其标记为历史结果。

## 8. 页面微文案建议

### 首屏说明

> 调整业务可配置策略，查看 AI 搜答案如何变化。每个结论都可以回到引用来源；固定样例用于发现策略改动中的回归。

### 草稿状态

> 本地演示草稿 · 策略改动会即时更新预览，尚未运行固定样例检查。

### 变化摘要

> 新增按肤质分组和 1 条踩坑提醒。当前分组范围包含“选购类、用法类”。

### 回归提示

> 发现 1 条回归：“防晒和粉底的先后顺序”遗漏“等待成膜”。当前分组范围同时作用于用法类问题。

### 修复结果

> 将分组范围收窄到“选购类”后重跑。用法类样例恢复原步骤顺序，“等待成膜”重新出现。

### 无证据状态

> 当前策略条件下没有足够的引用支持此结论。请调整来源条件或隐藏该结论，不要补写没有来源支撑的信息。

### 规则模拟声明

> 规则模拟原型：用于检查策略变化对固定样例的影响。样例期望要点由场景负责人独立标注；本结果不代表语义判断准确率或线上效果。
