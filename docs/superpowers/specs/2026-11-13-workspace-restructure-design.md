# 工作台重组设计（2026-11-13）

## 背景

旧版工作台按“参数类型”组织（内容依据 / 答案呈现 / 护栏规则），每个参数下重复显示设置者、来源、场景等信息，再加上侧栏、横向流程和页面标题互相重复，使用者不知道该点哪里、每块是什么意思。

产品定位重新明确为：**商业化、行业运营、社区治理三个角色（首期），共同搭建和维护 AI 搜对话卡片的呈现模板与帖子筛选机制。**

## 信息架构

```
顶栏：策略共建台 · 产品介绍 · 反馈治理(开发中) │ 当前场景 │ 账号身份 ▾ · ＋新建场景 · 重置演示
流程条：01 搭建卡片模板 ── 02 配置筛选策略 ── 03 运行回归检查
```

- 侧栏删除；流程条吸顶，是唯一的主导航。删除“建议演示时长”。
- **账号身份下拉框保留**，作用是账号权限隔离：任何账号都能查看其他角色的配置，但只能修改自己负责的部分。
- **＋新建场景**（顶栏右侧）：点开后选择“新建空白场景”（演示中直接进入护肤 · 选购怎么选这个案例的第 01 步）或“复用已有场景”（复用向导）。复用限定在**同一垂类内**：从“护肤 · 选购怎么选”复用到“护肤 · 怎么使用”，共用帖子池和已有组件；改配置项为“不按肤质分组、组件顺序、用法样例集”，待研发项为“用量与等待时长参数条”。复用不放进主流程。进入复用向导或反馈治理页时，流程条隐藏。

## 01 搭建卡片模板

定义答案卡的呈现结构。模板按内容类型划分（护肤测评 / 选购、旅行攻略、学习经验、家常菜做法），每个场景锁定一个模板版本。

页面左侧是角色页签：**行业运营 | 商业化 | 社区治理**。切换页签只是在看不同角色负责的模块；只有页签角色和账号身份一致时才能编辑，否则只读，并说明由谁负责。每个页签顶部有一句职责说明。

| 角色 | 模块 |
|---|---|
| 行业运营 | 一句话结论、按肤质分组及其适用范围、踩坑提醒、组件顺序 |
| 商业化 | 品牌说呈现位置（可以提出调整，冲突时转为待讨论，不会自动采纳）；品牌说挂载商品卡（待研发） |
| 社区治理 | 锁定：来源底栏与溯源、合作内容标识（法规要求）、“合作内容不早于结论”规则 |

依赖关系置灰：上游开关关闭时，下游设置置灰并标“未生效”。“按肤质分组”关闭 → “分组适用范围”置灰；组件顺序里已关闭的组件置灰、不编号、不可移动；来源底栏固定在末尾并标“社区治理锁定”。

**编辑模版**（标题栏按钮）：弹窗二选一——“新增卡片模块”（自然语言描述）或“上传模版”（JSON / Figma / Sketch / PDF / 图片）。提交后与新增策略相同，生成模拟工单。界面文案统一用“模块”，不出现“槽位”。

版本管理：顶部显示模板名、场景锁定的版本号和草稿版本号；版本历史按角色记录每次改动（示例数据加上当前草稿的实时条目）。

## 02 配置筛选策略

决定哪些帖子进入答案卡。角色页签形式与 01 相同。

**归属原则：谁承担规则的后果，谁负责这条规则。** 行业运营懂垂类，判断什么帖子对这类问题有用；商业化管合作内容的商业供给；社区治理守底线，其他角色的规则不能越过。

| 角色 | 规则 | 为什么归这个角色 |
|---|---|---|
| 行业运营 | 内容来源类型 | 评论是否有价值因垂类而异（护肤评论区常有肤感补充） |
| | 时效窗口 | 取决于垂类内容的更新节奏（防晒配方迭代快、有季节性） |
| | 笔记互动门槛（新增，`minNoteLikes`） | 各垂类互动量级不同；门槛过高会挤掉素人经验，需要懂垂类的人权衡 |
| | 优先展示亲身经验 | 护肤看上脸实测；“算不算亲身经验”由平台识别，运营只决定是否优先 |
| | 同肤质经验优先（新增，`preferMatchingPersona`，只排序） | 肤质匹配是护肤垂类特有的相关性判断 |
| 商业化 | 允许合作内容进入候选 | 场景是否开放给合作内容取决于投放规划 |
| | 合作内容须匹配提问人群（新增，`sponsoredPersonaMatch`） | 人群定向是商业化的本职，投错人群对品牌和用户都无益 |
| | 合作品牌须有品类资质（新增，对接资质库） | 资质审核本来就在商业化的广告审核链路里 |
| 社区治理 | 保留正反面经验（由行业运营移入） | 防止答案只剩正面种草；放在社区治理，避免在商业或运营压力下被关掉 |
| | 合作内容入卡上限（由商业化页签移入，`sponsoredCap`） | 上限是底线，商业化只能在范围内调整供给，不能自己定上限 |
| | 处罚期账号内容不入卡（新增，对接处罚记录） | 与社区已有处罚结果保持一致 |
| | 接入反馈评测结果（开发中） | 见“反馈治理” |

“商业内容必须标注”从筛选策略移到 01 卡片模板（社区治理 · 合作内容标识，锁定）：它决定的是帖子怎么呈现，不决定帖子能否入卡；且广告法要求广告可识别，不应是可关闭的开关。

**编辑策略**（标题栏按钮，替代原“新增策略”）：弹窗只列出当前账号角色负责的策略，可逐条删除或恢复；删除后该字段取中性值（不再过滤或排序），预览与入卡帖子立即更新，“恢复本页默认”可找回。弹窗下方可用自然语言描述新增策略，提交后生成模拟工单（与原流程相同）。

右侧预览除答案卡外，增加“入卡帖子变化”：列出相对基线新入卡和被筛掉的帖子，被筛掉的帖子附原因（来自引擎的 `filteredEvidence`）。

## 03 运行回归检查

沿用现有的覆盖与回归页，不改动。回归故事保持“按肤质分组的适用范围过宽”，现在由 01 的模板改动引起。页内“返回调整”的链接改为跳到 01。

## 反馈治理（首页讲解，工作台标“开发中”）

一套针对被用户反馈的帖子的评测、处置和复核链路：

1. 用户反馈：不相关、疑似软广、内容过时、信息不实。
2. 自动评测打分：从软广可能性、与问题的相关性、时效、信息可信度等维度打分，并附证据条数。
3. 分级处置：高置信时自动处置（移出答案卡或降权，可撤销）；中置信时进入社区治理人工复核队列；低置信时记录观察，反馈累积后重新评测。
4. 回流：复核结论用于校准阈值，典型帖子补进回归样例集。

价值：**效率**（自动分流，人工只处理中间档）和**成效**（处置准确率以复核结论为准，同类问题复发率下降）。

露出位置：首页讲完整链路；顶栏“反馈治理”进入“开发中”说明页；02 社区治理页签里一条置灰规则。
